# כפתורים - מתקדם

ב**כפתור לחיצה** חיברנו כפתור בשורה אחת וקראנו אותו עם `INPUT_PULLUP`. עכשיו נפתח את הכפתור, נחבר אותו כמו שצריך על מטריצה (breadboard), נבין למה כל כפתור צריך נגד, ונפתור את הבעיה שמפילה כמעט כל מתחיל: **ריטוט** (bouncing).

כל מה שכאן משתמש בלוח של הקורס, **Arduino Nano ESP32**. הפינים שלו עובדים ב-**3.3 V**, ולכן אנחנו מזינים את הכפתור מהפין **3.3V**, אף פעם לא מ-5 V.

## 1. איך בנוי כפתור לחיצה

הכפתור הריבועי הקטן שבערכה שלכם נקרא **מתג טקטילי** (tactile switch). יש בתוכו רק כמה חלקים:

- **בוכנה** (plunger) למעלה, החלק שהאצבע שלכם לוחצת עליו;
- **כיפת מתכת** (metal dome) דקה שמשמשת כקפיץ;
- **מגעים** (contacts) ממתכת בבסיס הפלסטיק;
- ארבע **רגליים** (legs), פיני המתכת שיוצאים מלמטה.

כשלוחצים, הכיפה נמעכת למטה ונוגעת במגע האמצעי, וזה סוגר את המעגל. אפשר אפילו להרגיש ולשמוע את ה"קליק". כשעוזבים, הכיפה קופצת חזרה למעלה והמעגל נפתח שוב.

![מבט מהצד, מבט מלמעלה וסמל חשמלי של כפתור לחיצה עם ארבע הרגליים שלו](assets/sensors/button-anatomy.svg)

### למה ארבע רגליים?

מתג צריך רק שני חיבורים, אז למה יש ארבעה? הרגליים מגיעות ב**שני זוגות**:

- רגליים **1 ו-2** מחוברות בתוך הכפתור ברצועת מתכת, ולכן הן **תמיד מחוברות**;
- גם רגליים **3 ו-4** **תמיד מחוברות**;
- **לחיצה** על הכפתור מחברת את הזוג 1–2 לזוג 3–4.

אז בעצם זה מתג אחד עם שתי רגליים בכל צד. הרגליים הנוספות גורמות לכפתור לשבת יציב על הלוח, ומאפשרות לחוט לעבור "דרך" הכפתור לצד השני.

> **בדקו בעצמכם:** כוונו מולטימטר למצב בדיקת רציפות (זה שמצפצף) וגעו בשתי רגליים. אם הוא מצפצף בלי לחיצה, שתי הרגליים האלה הן זוג. אם הוא מצפצף רק בזמן שאתם לוחצים, הן בצדדים שונים של המתג.

## 2. הצבת הכפתור על המטריצה

מתחת לחורים של המטריצה מסתתרות רצועות מתכת. באזור האמצעי, כל עמודה של חמישה חורים (a–e) היא רצועה אחת, וחמשת החורים שמתחת לרווח (f–j) הם רצועה אחרת. שני החצאים **לא** מחוברים מעבר לרווח האמצעי.

דחפו את הכפתור **מעל הרווח האמצעי**, כך ששתי רגליים יהיו בחצי העליון ושתיים בחצי התחתון. המרווח בין רגלי הכפתור מתאים בדיוק לזה.

![הכפתור מוצב מעל הרווח במטריצה, כשרגליים 1-2 בעמודה 5 ורגליים 3-4 בעמודה 7](assets/sensors/button-breadboard.svg)

כשהוא מוצב כך:

- רגליים 1 ו-2 נוחתות באותה עמודה (כאן עמודה 5), אחת מעל הרווח ואחת מתחתיו. כל 10 החורים של העמודה הזו הם עכשיו חיבור אחד.
- רגליים 3 ו-4 נוחתות בעמודה 7. כל 10 החורים של העמודה הזו הם חיבור נוסף.
- **לחיצה** על הכפתור מחברת את עמודה 5 לעמודה 7.

כלומר מחברים צד אחד של המעגל לאן שתרצו בעמודה 5, ואת הצד השני לאן שתרצו בעמודה 7.

> **טעות נפוצה:** אם מסובבים את הכפתור ברבע סיבוב, שתי רגליים שתמיד מחוברות מגיעות לשתי עמודות שונות. חברו חוטים לשתי העמודות האלה והכפתור ייראה "לחוץ תמיד". הטריק הבטוח: חברו את החוטים לשתי רגליים ש**באלכסון** זו לזו (1 ו-4, או 2 ו-3). הן תמיד בצדדים שונים של המתג, לא משנה איך הכפתור יושב.

## 3. הוספת נגד pull-down

הרעיון הכי פשוט הוא לחבר צד אחד של הכפתור ל-**3.3V** ואת הצד השני לפין **D2**. כשהכפתור לחוץ, D2 מקבל 3.3 V וקורא HIGH. אבל מה D2 קורא כשהכפתור משוחרר?

התשובה היא: **כל דבר**. כפתור משוחרר מחבר את D2 לשום דבר. פין שלא מחובר לשום דבר נקרא **צף** (floating). הוא מתנהג כמו אנטנה קטנטנה וקולט רעש מהיד שלכם, מחוטים סמוכים ומחיווט החשמל שבקירות. הוא קורא HIGH ו-LOW אקראיים, והתוכנית שלכם חושבת שרוח רפאים לוחצת על הכפתור.

הפתרון הוא **נגד משיכה למטה** (pull-down resistor): נגד 10 kΩ מ-D2 ל-**GND**.

![בלי נגד הפין צף; עם pull-down של 10 kΩ הוא קורא LOW כשמשוחרר ו-HIGH כשלחוץ](assets/sensors/button-pulldown.svg)

- **משוחרר:** הנגד "מושך" בעדינות את D2 למטה ל-GND, כך שהוא קורא **LOW**.
- **לחוץ:** הכפתור מחבר את D2 ישירות ל-3.3V. הכפתור מנצח את הנגד, ולכן D2 קורא **HIGH**.

### למה 10 kΩ?

- **לא 0 Ω (חוט רגיל):** לחיצה על הכפתור הייתה מחברת את 3.3V ישירות ל-GND. זה קצר חשמלי.
- **לא קטן מדי:** זרם עובר בנגד בכל פעם שלוחצים. עם 10 kΩ הוא רק 3.3 V ÷ 10 000 Ω = 0.33 mA, כלומר כלום.
- **לא גדול מדי:** נגד ענק (נגיד 10 MΩ) מושך כל כך חלש שהרעש עדיין יכול לנצח, והפין מתחיל לצוף שוב.

כל ערך בין בערך 4.7 kΩ ל-47 kΩ עובד. 10 kΩ הוא הבחירה הרגילה. פסי הצבע שלו הם **חום, שחור, כתום**.

### החיווט על המטריצה

![חיווט על המטריצה: 3.3V לפס ה-+, מגשר לכפתור, ו-D2 ונגד 10 kΩ ל-GND בצד השני](assets/sensors/button-pulldown-breadboard.svg)

1. חברו את הפין **3.3V** של ה-Nano ESP32 לפס ה-**+**, ואת **GND** לפס ה-**−**.
2. הציבו את הכפתור מעל הרווח האמצעי.
3. חוט קצר מפס ה-**+** לצד אחד של הכפתור (העמודה האדומה).
4. חוט מהצד השני של הכפתור (העמודה הירוקה) ל-**D2**.
5. נגד ה-10 kΩ מאותה עמודה ירוקה לפס ה-**−**.

## 4. קריאת HIGH או LOW עם ה-Arduino

```c
const int BUTTON_PIN = D2;

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT);          // a plain input: our resistor does the pulling
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  int state = digitalRead(BUTTON_PIN); // HIGH (1) or LOW (0)

  if (state == HIGH) {
    Serial.println("Pressed");
    digitalWrite(LED_BUILTIN, HIGH);   // the LED follows the button
  } else {
    Serial.println("Released");
    digitalWrite(LED_BUILTIN, LOW);
  }
  delay(100);
}
```

פתחו את **Tools → Serial Monitor** וכוונו אותו ל-**115200 baud**. לחצו על הכפתור ותראו את הטקסט משתנה, ואת ה-LED הכתום של הלוח נדלק.

עם נגד pull-down הלוגיקה היא ה"טבעית": **לחוץ = HIGH**, משוחרר = LOW.

> **שמות פינים ב-Nano ESP32:** כתבו `D2`, ולא רק `2`. הלוח יכול למספר את הפינים שלו בשתי דרכים (מספרי Arduino או מספרי ה-GPIO של שבב ה-ESP32), ו-`D2` תמיד אומר את הפין שכתוב עליו "D2" על הלוח.

**נסו את זה:** הוציאו את הנגד והריצו את הסקיצה שוב. קרבו את האצבע לחוטים בלי ללחוץ. הפין ה"צף" מתחיל להדפיס ערכים אקראיים.

## 5. ריטוט

עכשיו בואו נספור לחיצות. הסקיצה הזו מחפשת את הרגע שבו הפין עובר מ-LOW ל-HIGH:

```c
const int BUTTON_PIN = D2;
int lastState = LOW;
int presses = 0;

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT);
}

void loop() {
  int state = digitalRead(BUTTON_PIN);
  if (state == HIGH && lastState == LOW) {   // it just went from LOW to HIGH
    presses++;
    Serial.print("Presses: ");
    Serial.println(presses);
  }
  lastState = state;
}
```

לחצו על הכפתור עשר פעמים. לפעמים המונה קופץ ב-2 או ב-3 על לחיצה אחת. הקוד נכון; הבעיה היא בכפתור.

כשכיפת המתכת פוגעת במגע, היא לא נוחתת נקי. היא קופצת למעלה ולמטה כמה פעמים, כמו כדור שנופל על הרצפה, לפני שהיא מתייצבת. זה לוקח רק בערך **1 עד 5 מילישניות**, מהר מדי בשביל שתשימו לב. אבל ה-ESP32 קורא את הפין מיליוני פעמים בשנייה, ולכן הוא רואה כל קפיצה כלחיצה נפרדת. זה יכול לקרות גם בשחרור.

![מה שמצפים לו: מדרגה אחת נקייה. מה שקורה באמת: כמה פולסים מהירים של HIGH-LOW לפני שהאות מתייצב](assets/sensors/bounce.svg)

התיקון של זה נקרא **ניקוי ריטוט** (debouncing). אפשר לעשות אותו בחומרה או בתוכנה.

## 6. ניקוי ריטוט בחומרה

הרעיון הוא לגרום למתח בפין להשתנות **לאט**, כך שהקפיצות הקצרות מוחלקות לפני שהן מגיעות לפין. מוסיפים נגד וקבל, שנקראים יחד **מסנן RC** (RC filter):

![נגד 10 kΩ בטור וקבל 1 µF ל-GND מחליקים את האות הקופצני לעלייה איטית ב-D2](assets/sensors/debounce-rc.svg)

- **קבל** (capacitor) הוא כמו דלי קטן למטען. המתח עליו לא יכול לקפוץ; הוא רק עולה ככל שהקבל מתמלא.
- **נגד ה-10 kΩ בטור** מגביל כמה מהר הוא יכול להתמלא.
- כשלוחצים, הקבל מתמלא בהדרגה, כך שהמתח ב-D2 מטפס בעקומה עדינה אחת. כל קפיצה נמשכת זמן קצר מדי בשביל לרוקן את הדלי, ולכן הפין אף פעם לא רואה אותה.

כמה לאט זה "לאט"? מכפילים את הנגד בקבל: **R × C = 10 kΩ × 1 µF = 10 ms**. זה ארוך יותר מהקפיצות, אבל עדיין מהר מדי בשביל שבן אדם ישים לב.

- **יתרונות:** אין צורך בקוד נוסף, וזה עובד עם כל תוכנית.
- **חסרונות:** עוד שני רכיבים לכל כפתור. כדי לקבל קצוות נקיים במיוחד, מהנדסים מוסיפים גם שבב **Schmitt trigger** (כמו ה-74HC14) אחרי המסנן, שהופך את העקומה האיטית בחזרה למדרגה חדה.

## 7. ניקוי ריטוט בתוכנה: `debouncedRead()`

רוב הפרויקטים מתקנים את הריטוט בקוד, כי קוד הוא בחינם. הרעיון פשוט:

1. קוראים את הפין.
2. אם הוא **שונה** מהפעם הקודמת, משהו קורה, אבל ייתכן שהוא עדיין קופץ. **מחכים 5 ms.**
3. קוראים אותו **שוב**. עד עכשיו הקפיצות כבר נגמרו, אז אפשר לסמוך על הערך הזה.

אם שום דבר לא השתנה, אין מה לבדוק, ולכן הפונקציה חוזרת מיד והתוכנית לא מואטת.

![ניקוי ריטוט בתוכנה: מזהים שינוי, הקוד מחכה 5 ms, ואז קורא שוב את הפין שכבר התייצב](assets/sensors/debounce-software.svg)

```c
const int BUTTON_PIN = D2;
int lastState = LOW;
int presses = 0;

// Reads a pin but ignores the bouncing.
// lastState is the value this pin had last time.
int debouncedRead(int pin, int lastState) {
  int state = digitalRead(pin);
  if (state != lastState) {      // a change! but it may still be bouncing...
    delay(5);                    // ...so wait 5 ms
    state = digitalRead(pin);    // ...and read again
  }
  return state;
}

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT);
}

void loop() {
  int state = debouncedRead(BUTTON_PIN, lastState);
  if (state == HIGH && lastState == LOW) {
    presses++;
    Serial.print("Presses: ");
    Serial.println(presses);
  }
  lastState = state;
}
```

השינוי היחיד לעומת המונה מחלק 5 הוא ש-`digitalRead()` הפך ל-`debouncedRead()`. עכשיו כל לחיצה נספרת בדיוק פעם אחת.

כמה דברים ששווה לשים לב אליהם:

- אם הקריאה השנייה מחזירה את הערך ה**ישן**, ה"שינוי" היה סתם קוץ קצר של רעש, ומתעלמים ממנו. זה בונוס.
- הפונקציה מקבלת את `lastState` כפרמטר במקום לשמור אותו בתוכה. כך אפשר להשתמש באותה פונקציה לכמה כפתורים, לכל אחד משתנה `lastState` משלו.
- **5 ms** מספיקות לכפתורים שבערכה שלכם. מתג גדול, ישן או זול עלול לקפוץ זמן רב יותר. אם הוא עדיין סופר כפול, נסו 10 או 20 ms.
- בזמן ש-`delay(5)` רץ, הלוח לא עושה שום דבר אחר. בשביל כפתור זה בסדר. בהמשך נלמד לחכות עם `millis()` בלי לעצור את התוכנית.

## תוספת: נגד ה-pull-up המובנה

לא תמיד צריך להוסיף נגד בעצמכם. בתוך שבב ה-ESP32, לכל פין יש נגד (בערך **45 kΩ**) שאפשר לחבר ל-3.3V דרך התוכנה. זה ה-**pull-up הפנימי** (internal pull-up), ו-`INPUT_PULLUP` מפעיל אותו.

כשה-pull-up נמצא בתוך השבב, החיווט נהיה פשוט יותר: הכפתור הולך בין **D2** ל-**GND**, וזהו. בלי נגד ובלי חוט 3.3V.

![נגד ה-pull-up הפנימי בתוך ה-Nano ESP32 מחזיק את D2 ב-HIGH; לחיצה על הכפתור מחברת את D2 ל-GND](assets/sensors/button-pullup.svg)

המלכודת היא שהלוגיקה **הפוכה**:

- **משוחרר:** הנגד הפנימי מושך את D2 למעלה ל-3.3V, כך שהוא קורא **HIGH**.
- **לחוץ:** הכפתור מחבר את D2 ל-GND, כך שהוא קורא **LOW**.

אותו מונה עם ה-pull-up הפנימי צריך רק שלושה שינויים קטנים:

```c
const int BUTTON_PIN = D2;
int lastState = HIGH;                  // 1. released is now HIGH
int presses = 0;

int debouncedRead(int pin, int lastState) {
  int state = digitalRead(pin);
  if (state != lastState) {
    delay(5);
    state = digitalRead(pin);
  }
  return state;
}

void setup() {
  Serial.begin(115200);
  pinMode(BUTTON_PIN, INPUT_PULLUP);   // 2. switch on the internal pull-up
}

void loop() {
  int state = debouncedRead(BUTTON_PIN, lastState);
  if (state == LOW && lastState == HIGH) {   // 3. a press is now HIGH -> LOW
    presses++;
    Serial.print("Presses: ");
    Serial.println(presses);
  }
  lastState = state;
}
```

| | pull-down חיצוני | pull-up פנימי |
|---|---|---|
| הכפתור מחבר את D2 ל- | 3.3V | GND |
| רכיבים נוספים | נגד 10 kΩ | אין |
| `pinMode` | `INPUT` | `INPUT_PULLUP` |
| קריאה כשמשוחרר | LOW | HIGH |
| קריאה כשלחוץ | HIGH | LOW |

> **טוב לדעת:** ל-ESP32 יש גם **pull-down** פנימי, שמופעל עם `INPUT_PULLDOWN`. ל-Arduino Uno הקלאסי יש רק pull-up, ולכן רוב דוגמאות ה-Arduino שתמצאו ברשת משתמשות ב-`INPUT_PULLUP` וב"לחוץ = LOW".

3. **שני כפתורים:** הוסיפו כפתור שני עם ה-pull-up הפנימי. כפתור אחד סופר למעלה, והשני סופר למטה. השתמשו בפונקציית `debouncedRead()` אחת ובשני משתני `lastState`.
4. **כמה זמן הוא היה לחוץ?** השתמשו ב-`millis()` כדי למדוד כמה זמן הכפתור הוחזק לחוץ, והדפיסו את זה כשאתם עוזבים.
