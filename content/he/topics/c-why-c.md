# למה C?

אתם כבר יודעים Python, ו-Python קלה יותר לכתיבה. אז למה ללמוד עוד שפה? כי המחשבים הקטנים שבתוך מכונות מריצים בעיקר C. אם אתם רוצים לבנות רובוט, רחפן או בקר מנוע, במוקדם או במאוחר תקראו ותכתבו C.

## C נמצאת בכל מכונה

C נוצרה ב-1972 והיא עדיין אחת השפות הנפוצות בעולם. במכטרוניקה וברובוטיקה פוגשים אותה כמעט בכל רמה:

| איפה | מה כתוב ב-C (או בקרובת המשפחה שלה, C++) |
|-------|--------------------------------------------------|
| **מיקרו-בקרים** (microcontrollers) | כמעט כל הקושחה (firmware): Arduino, ESP32, STM32, PIC. "שפת" Arduino היא C/C++ |
| **דרייברים למנועים ובקרי טיסה** | לולאות הבקרה המהירות שקוראות חיישנים ומפעילות מנועים |
| **ציוד תעשייתי** | בקרי רובוטים, סביבות ריצה של PLC, מכונות CNC, חיישנים עם מעבד מובנה |
| **מערכות הפעלה** | Linux, Windows ומערכות ההפעלה בזמן אמת שמשמשות ברובוטים |
| **כלי ה-Python שלכם** | המפרש (interpreter) של Python עצמו והליבה של NumPy כתובים ב-C |

גם יצרני השבבים מפרסמים את דוגמאות הקוד והספריות שלהם ב-C. כשקונים חיישן חדש או דרייבר למנוע, קוד הדוגמה שמגיע איתו הוא כמעט תמיד C.

## C ו-Python זו לצד זו

| | Python | C |
|---|--------|---|
| **איך זה רץ** | מפרש קורא את התוכנית שורה אחרי שורה בזמן הריצה | מהדר (compiler) מתרגם את כל התוכנית לקוד מכונה לפני שהיא רצה |
| **מה זה צריך** | מפרש, ובדרך כלל מערכת הפעלה | כלום. התוכנית יכולה לרוץ ישירות על השבב החשוף |
| **מהירות** | איטית | לעיתים קרובות מהירה פי 10 עד 100 בלולאות ובחישובים |
| **זיכרון** | מנוהל בשבילכם, עם הרבה תקורה | אתם מחליטים בדיוק כמה בתים תופס כל משתנה |
| **תזמון** | יכולה לעצור ברגעים לא צפויים | צפוי |
| **חומרה** | נגישה דרך ספריות | נגישה ישירות, עד לביט בודד של פין בודד |
| **טעויות** | הודעות שגיאה ברורות בזמן הריצה | הרבה שגיאות נתפסות על ידי המהדר, אבל לתוכנית שרצה אין רשת ביטחון |

הסעיפים הבאים מסבירים למה ההבדלים האלה חשובים במכונה.

## היא נכנסת לשבב קטן

ל-Arduino Uno יש **2 KB** של RAM ו-**32 KB** של זיכרון תוכנית. מפרש Python פשוט לא נכנס לשם: MicroPython, הגרסה הקטנה של Python שנועדה למיקרו-בקרים, צריכה בערך 256 KB של זיכרון תוכנית ו-16 KB של RAM עוד לפני שסופרים את התוכנית שלכם.

לתוכנית C אין מפרש שצריך לסחוב איתה. רק הקוד שלכם ופונקציות הספרייה שאתם באמת משתמשים בהן נכנסים לשבב, כך שתוכנית שימושית יכולה לתפוס כמה אלפי בתים. שבבים קטנים הם זולים וצורכים מעט חשמל, וזה חשוב כשמוצר מיוצר במיליונים או רץ על סוללה.

גם השימוש בזיכרון נמצא בשליטתכם. ב-Python, אפילו מספר שלם קטן תופס בערך 28 בתים. ב-C, `int` תופס 4 בתים ו-`char` תופס בית אחד, לא יותר.

## היא מהירה

ב-Python, כל שורה נבדקת מחדש בכל פעם שהיא רצה: מה הטיפוס של המשתנה הזה, מה המשמעות של `+` עבורו, איפה הוא שמור? ב-C, המהדר עונה על כל השאלות האלה פעם אחת, מראש. מה שרץ על השבב הוא רק קוד המכונה שעושה את העבודה.

מיקרו-בקר חלש בהרבה מהמחשב הנייד שלכם, ולכן ההבדל הזה קובע מה אפשרי. לולאת בקרה של מנוע עשויה להצטרך לרוץ אלפי פעמים בשנייה, ובכל סיבוב היא צריכה לקרוא חיישנים, לחשב ולעדכן את הפלט.

## התזמון שלה צפוי

בבקרה, להיות **בזמן** חשוב בדיוק כמו להיות נכון. רובוט מאזן שמתקן את המנועים שלו כל 1 ms עובד טוב. אם תיקון אחד מגיע באיחור של 20 ms, הוא עלול ליפול.

Python מנקה זיכרון שלא בשימוש באופן אוטומטי (זה נקרא **איסוף זבל**, garbage collection), והיא עושה את זה מתי ש*היא* מחליטה. התוכנית שלכם עוצרת לרגע, ואי אפשר לדעת מתי או לכמה זמן. ב-C אין אוסף זבל ושום דבר לא רץ מאחורי הגב שלכם, כך שאותו קוד לוקח את אותו זמן בכל סיבוב. זה מה שמאפשר בקרה ב**זמן אמת** (real-time).

## היא מדברת ישירות עם החומרה

במיקרו-בקר, פינים, טיימרים ופורטים של תקשורת נשלטים דרך **רגיסטרים** (registers): מקומות מיוחדים בזיכרון בתוך השבב. C יכולה לקרוא ולכתוב אותם ישירות:

```c
PORTB = PORTB | 0b00100000;   // turn on one pin (the LED on an Arduino Uno)
```

השורה הבודדת הזו הופכת לפקודת מכונה אחת או שתיים. C גם מאפשרת לכתוב פונקציות **פסיקה** (interrupt), שהשבב קורא להן בעצמו ברגע שמשהו קורה, למשל כשמגיע פולס מאנקודר (encoder) של מנוע.

## אתם שולטים בכל בית

התקנים מדברים זה עם זה בבתים. חיישן יכול לשלוח מספר של 16 ביט בדיוק כשני בתים, ודרייבר מנוע יכול לצפות לפקודה של בדיוק 5 בתים. לטיפוסים ב-C יש גודל ידוע וקבוע, כך שאפשר לבנות ולקרוא הודעות כאלה במדויק. תשתמשו בזה ביחידות על ייצוג בינארי ועל תקשורת טורית.

## במה Python עדיין טובה יותר

C היא לא "טובה יותר" מ-Python. היא טובה יותר **לעבודות מסוימות**. תוכנית Python קצרה יותר, מהירה יותר לכתיבה וקלה יותר לדיבוג, ול-Python יש ספריות מצוינות לניתוח נתונים, ראייה ממוחשבת ובינה מלאכותית.

C גורמת לכם לעבוד יותר, והיא מגינה עליכם פחות. למשל, כתיבה מעבר לסוף של מערך לא נעצרת עם הודעת שגיאה. התוכנית פשוט ממשיכה עם נתונים פגומים.

לכן הרבה רובוטים משתמשים בשתיהן:

| חלק ברובוט | תפקיד טיפוסי | שפה |
|-------------------|-------------|----------|
| המחשב הראשי (PC או Raspberry Pi) | ראייה, תכנון מסלול, ממשק משתמש, רישום נתונים | Python |
| המיקרו-בקרים | קריאת חיישנים, הפעלת מנועים, לולאות בקרה, בטיחות | C |

> **כלל אצבע:** ככל שהקוד קרוב יותר לחומרה, וככל שהוא תלוי יותר בתזמון מדויק, כך גדל הסיכוי שהוא כתוב ב-C.

החדשות הטובות הן שאתם כבר יודעים לתכנת. העמוד הבא מראה איך הרעיונות שאתם מכירים מ-Python נכתבים ב-C.
