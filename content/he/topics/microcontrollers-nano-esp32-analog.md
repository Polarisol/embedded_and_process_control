# הפינים האנלוגיים של Nano ESP32

העולם האמיתי הוא לא רק דולק וכבוי. חדר הוא קצת חשוך או מאוד מואר, כפתור סיבובי מסובב קצת או עד הסוף, המים פושרים או חמים. חיישנים הופכים את הדברים האלה ל**מתח** שיכול להיות כל ערך בין 0 V למתח האספקה. פין **אנלוגי** מודד את המתח הזה ונותן לתוכנית שלכם מספר.

![ה-Nano ESP32 כשהפינים האנלוגיים שלו מודגשים: A0 עד A3 תמיד עובדים, A4 עד A7 לא עובדים כשה-Wi-Fi דולק, A4 ו-A5 הם גם I2C; פיני ה-D בצד ימין הם דיגיטליים בלבד](assets/nano-esp32/analog-pins.svg)

## אילו פינים הם אנלוגיים?

ל-Nano ESP32 יש **8 כניסות אנלוגיות**, **A0 – A7**, בצד שמאל של הלוח.

| פינים | הערות |
|------|-------|
| **A0 – A3** | תמיד עובדים. השתמשו בהם קודם |
| **A4 – A7** | לא עובדים כשה-**Wi‑Fi** דולק, כי הרדיו משתמש באותו ממיר בתוך השבב. מתאימים לפרויקטים בלי Wi‑Fi |
| **A4, A5** | הם גם ערוץ ה-**I2C** ‏(SDA ו-SCL). אם חיישן משתמש ב-I2C, שני הפינים האלה תפוסים |

**פיני ה-D לא יכולים לקרוא מתח אנלוגי.** הם דיגיטליים בלבד. לעומת זאת, הפינים האנלוגיים יכולים לעבוד גם כפינים דיגיטליים עם `digitalRead()` ו-`digitalWrite()`.

## ממתח למספר: ה-ADC

בתוך השבב יש **ADC** ‏(Analog-to-Digital Converter, ממיר אנלוגי-לדיגיטלי). הוא מודד את המתח על הפין והופך אותו למספר שלם. ‏`analogRead(pin)` נותן לכם את המספר הזה:

![סולם מתח מ-0 V עד 3.3 V מעל סולם מספרים מ-0 עד 4095: ‏0.825 V הוא 1024, ‏1.65 V הוא 2048, ‏2.475 V הוא 3071 ו-3.3 V הוא 4095](assets/nano-esp32/adc.svg)

ל-ADC של ה-Nano ESP32 יש **12 ביטים**, אז המספר נע בין **0** ל-**4095** (2¹² = 4096 ערכים שונים):

| המתח על הפין | `analogRead()` מחזיר |
|--------------------|----------------------|
| 0 V | 0 |
| 1.65 V (חצי) | בערך 2048 |
| 3.3 V | 4095 |

כדי להפוך את המספר בחזרה לוולטים: `volts = value * 3.3 / 4095.0`. או תנו ללוח לעשות את זה: `analogReadMilliVolts(pin)` מחזיר את המתח במיליוולטים, כבר מתוקן לשגיאות המדידה הקטנות של השבב.

> **מגיעים מ-Arduino Uno?** ל-Uno יש ADC של 10 ביטים ופינים של 5 V, אז הוא קורא 0 – 1023 עבור 0 – 5 V. בדוגמאות שנכתבו ל-Uno צריך לשנות את המספרים ל-4095 ול-3.3 V.

## דוגמה: קריאת פוטנציומטר

**פוטנציומטר** (כפתור סיבובי) הוא הדרך הקלה ביותר לנסות פין אנלוגי. חברו את שני הקצוות שלו ל-**3V3** ול-**GND**, ואת הרגל האמצעית שלו, ה**מגב** (wiper), ל-**A0**. סיבוב הכפתור מזיז את המגב מ-0 V עד 3.3 V:

![פוטנציומטר של 10 קילו-אוהם עם קצה אחד ב-3V3, השני ב-GND והמגב ב-A0; סיבוב הכפתור נותן 0 V ו-0, ‏1.65 V ו-2048, או 3.3 V ו-4095](assets/nano-esp32/analog-pot.svg)

```c
const int POT_PIN = A0;

void setup() {
  Serial.begin(115200);
}

void loop() {
  int value = analogRead(POT_PIN);         // 0 to 4095
  float volts = value * 3.3 / 4095.0;      // back to volts
  Serial.print(value);
  Serial.print("  ->  ");
  Serial.print(volts);
  Serial.println(" V");
  delay(200);
}
```

**נסו את זה:** פתחו את **Tools → Serial Plotter** ב-Arduino IDE וסובבו את הכפתור. תקבלו גרף חי של תנועת היד שלכם.

## שימוש במספר: `map()`

מספר גולמי בין 0 ל-4095 הוא כמעט אף פעם לא מה שאתם צריכים. ‏`map()` ממיר מספר מתחום אחד לתחום אחר. כאן הכפתור קובע את העוצמה של נורית על D2, שה-PWM שלה נע בין 0 ל-255:

```c
const int POT_PIN = A0;
const int LED_PIN = D2;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  int value = analogRead(POT_PIN);                 // 0 to 4095
  int brightness = map(value, 0, 4095, 0, 255);    // 0 to 255
  analogWrite(LED_PIN, brightness);
}
```

אותו רעיון הופך קריאה למעלות, לאחוזים או לזווית של סרוו: `map(value, 0, 4095, 0, 180)`.

## אף פעם לא יותר מ-3.3 V

פין אנלוגי מודד עד 3.3 V, ו**יותר מ-3.3 V יכול להרוס אותו**. הרבה חיישנים שנבנו ל-Uno מוציאים עד 5 V. כדי לקרוא אותם, הורידו את המתח בעזרת **מחלק מתח**: שני נגדים בטור, כשהפין מחובר ביניהם.

![יציאה של חיישן 5 V עוברת דרך R1 = 10 קילו-אוהם ו-R2 = 15 קילו-אוהם אל GND; הנקודה שביניהם מחוברת ל-A0. ‏5 V כפול 15 חלקי 25 הם 3.0 V, בבטחה מתחת ל-3.3 V](assets/nano-esp32/analog-divider.svg)

הפין רואה `V_OUT × R2 ÷ (R1 + R2)`. עם 10 kΩ ו-15 kΩ, ‏5 V הופכים ל-3.0 V. בקוד, הכפילו בחזרה: `sensorVolts = volts * 25.0 / 15.0`.

## קריאות רועשות

קראו את אותו פין פעמיים ולעתים קרובות תקבלו שני מספרים קצת שונים, כמו 2031 ו-2044. ה**רעש** הזה נורמלי: המתח עצמו זז קצת, וגם ה-ADC. הפתרון הקל הוא **לחשב ממוצע** של כמה קריאות:

```c
int readAverage(int pin) {
  long sum = 0;
  for (int i = 0; i < 16; i++) {
    sum += analogRead(pin);
  }
  return sum / 16;
}
```

וגם אז, אל תצפו שהספרות האחרונות יהיו מדויקות. ה-ADC של ה-ESP32 גם פחות מדויק קרוב מאוד ל-0 V ול-3.3 V, אז כשאפשר, תכננו את המעגל כך שיישאר באמצע התחום.

## ומה עם יציאה אנלוגית?

ה-Nano ESP32 **לא יכול להוציא מתח אנלוגי אמיתי**. אין DAC ‏(Digital-to-Analog Converter, ממיר דיגיטלי-לאנלוגי) על הפינים שלו. ‏`analogWrite()` הוא **PWM** על פין דיגיטלי: הפין עדיין עובר בין 3.3 V ל-0 V, מהר מאוד. לנוריות ולמנועים זה כל מה שצריך, כי הם מרגישים את הממוצע. הפריט על הפינים הדיגיטליים מסביר את ה-PWM.

## סיכום

- ‏**A0 – A7** קוראים מתח בין **0 V ל-3.3 V**. ‏**A4 – A7** לא עובדים כשה-Wi‑Fi דולק.
- ‏`analogRead(pin)` מחזיר **0 – 4095** ‏(12 ביטים). ‏`volts = value * 3.3 / 4095.0`, או השתמשו ב-`analogReadMilliVolts(pin)`.
- ‏`map()` הופך את המספר למשהו שימושי.
- **אף פעם לא יותר מ-3.3 V** על פין. השתמשו במחלק מתח לאות של 5 V.
- חשבו ממוצע של כמה קריאות כדי להרגיע את הרעש.

## אתגר

**מד אור:** חברו חיישן אור (LDR) עם נגד של 10 kΩ כמחלק מתח ל-A0. הדפיסו את רמת האור באחוזים (0 % חשוך, 100 % מואר) והדליקו נורית על D2 כשנהיה חשוך. אחר כך גרמו לנורית להיות חזקה יותר ככל שנהיה חשוך יותר.
