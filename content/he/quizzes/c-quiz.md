# בוחן יסודות C, sprintf ו-sscanf

ענו על כל השאלות, ואז לחצו על **הגשת התשובות** כדי לראות את הציון ואת התיקונים.

## למה משתמשים ב-C, ולא ב-Python, על שבבים קטנים כמו הארדואינו? בחרו את כל התשובות הנכונות.
- [x] היא רצה מהר
  > נכון. C מתורגמת לשפה של השבב עצמו לפני שהיא רצה, ולכן היא לרוב מהירה פי 10 עד 100 מ-Python.
- [ ] היא מזהירה אתכם כשאתם עושים טעות בזמן שהתוכנית רצה
  > זה בדיוק הפוך. Python נותנת הודעות שגיאה ברורות, אבל לתוכנית C שרצה אין רשת ביטחון.
- [x] היא יכולה לשלוט בחומרה ישירות ובדיוק
  > נכון. C יכולה לעשות את זה.
- [x] היא קטנה מספיק כדי להיכנס לשבב זעיר
  > נכון. בארדואינו Uno יש רק 32 KB לתוכניות. Python לא נכנסת לשם, אבל תוכנית C יכולה לתפוס רק כמה KB.
- [ ] היא קצרה וקלה יותר לכתיבה מ-Python
  > Python בדרך כלל קצרה וקלה יותר. בוחרים ב-C בגלל מהירות, גודל ושליטה, לא כי היא קלה.
> מיקרו-בקר הוא שבב קטן ואיטי עם מעט מאוד זיכרון. C מהירה, קטנה ויכולה לדבר ישירות עם הפינים של השבב, ולכן היא הבחירה הטבעית שם. Python נשארת על המחשב, שם קל יותר לכתוב בה.

## אתם מתרגמים Python ל-C. אילו שורות C נכונות **וגם** עושות את מה שכתוב בהערה שלהן? בחרו את כל התשובות הנכונות.
- [ ] `area = r ** 2;      // r squared`
  > ב-C אין אופרטור `**`. השתמשו ב-`r * r`, או ב-`pow(r, 2)` עם `#include <math.h>`.
- [x] `count++;           // add one to count`
  > נכון. `x++` מוסיף אחד ו-`x--` מחסיר אחד. גם `count += 1;` עובד.
- [ ] `half = 7 // 2;     // whole-number division`
  > ב-C, `//` פותח הערה, אז המהדר רואה רק `half = 7` והנקודה-פסיק הולכת לאיבוד. חילוק שלמים כותבים עם `/` אחד.
- [ ] `avg = 7 / 2;       // gives 3.5`
  > `7` ו-`2` הם שניהם `int`, אז C זורקת את השבר והתוצאה היא `3`. כתבו `7.0 / 2` כדי לקבל `3.5`.
- [x] `if (x > 0 && x < 10)   // x is between 0 and 10`
  > נכון. את `0 < x < 10` של Python צריך לפצל לשתי השוואות שמחוברות ב-`&&`.
> ההבדלים העיקריים באופרטורים לעומת Python: אין `**` (משתמשים ב-`pow`), אין `//` (חילוק של שני `int` כבר זורק את השבר), יש `++` ו-`--`, ואת `and`, `or`, `not` כותבים `&&`, `||`, `!`.

## מה הקוד הזה מדפיס?
```c
int v[5] = {3, 7};
v[3] = v[0] + v[1];
printf("%d %d\n", v[3] / 4, v[4]);
```
- [ ] `2.5 0`
  > `v[3]` הוא `int` וגם `4` הוא `int`, אז החילוק זורק את השבר.
- [ ] `2` ואחריו ערך זבל
  > המספר הראשון נכון, אבל `v[4]` הוא לא זבל: כשנותנים חלק מערכי ההתחלה בסוגריים מסולסלים, שאר המערך מתאפס.
- [x] `2 0`
  > נכון! `v[3]` הוא `3 + 7 = 10`, `10 / 4` הוא `2` בחילוק שלמים, ו-`v[4]` אופס על ידי האתחול החלקי.
- [ ] `2.5` ואחריו ערך זבל
  > שתי טעויות: `int / int` נותן מספר שלם, והערכים החסרים ב-`{3, 7}` מתמלאים באפסים, לא בזבל.
> `int v[5] = {3, 7};` נותן `3, 7, 0, 0, 0`. בלי סוגריים מסולסלים (`int v[5];`) כל חמשת האיברים היו מכילים זבל. ו-`int / int` הוא תמיד מספר שלם.

## המשתנה `name` הוצהר כך: `char name[20] = "Dana";`. איזו שורה משנה נכון את הטקסט שלו ל-`"Noa"`?
- [x] `strcpy(name, "Noa");`
  > נכון. `strcpy` מעתיקה טקסט חדש לתוך המחרוזת. היעד בא ראשון, בדיוק כמו שקוראים `name = "Noa"`.
- [ ] `name = "Noa";`
  > הצורה `= "..."` עובדת רק בהצהרה. אחר כך המהדר מסרב להציב ערך במערך.
- [ ] `strcat(name, "Noa");`
  > `strcat` מוסיפה טקסט לסוף, אז `name` יהפוך ל-`"DanaNoa"`.
- [ ] `strcpy("Noa", name);`
  > הארגומנטים הפוכים. השורה הזו מנסה להעתיק לתוך הטקסט `"Noa"`, שהוא לא מקום שאפשר לכתוב אליו.
> מחרוזת ב-C היא מערך של `char` שמסתיים ב-`'\0'` נסתר. אחרי ההצהרה משנים אותה עם פונקציות מ-`string.h`: `strcpy` כדי להחליף, `strcat` כדי להוסיף, `strcmp` כדי להשוות ו-`strlen` כדי למדוד.

## מה הקוד הזה מדפיס?
```c
int mode = 2;

switch (mode) {
    case 1:
        printf("A");
    case 2:
        printf("B");
    case 3:
        printf("C");
        break;
    default:
        printf("D");
}
```
- [ ] `B`
  > ב-`case 2` אין `break`, אז התוכנית לא עוצרת אחרי שהיא מדפיסה `B`.
- [ ] `BCD`
  > ה-`break` בסוף `case 3` עוצר את ה-switch לפני שהוא מגיע ל-`default`.
- [ ] `ABC`
  > ה-switch קופץ ישר ל-`case 2`. מדלגים על `case 1` כי `mode` הוא לא 1.
- [x] `BC`
  > נכון! ה-switch קופץ ל-`case 2`, מדפיס `B`, ממשיך ("נופל") לתוך `case 3` כי אין `break`, מדפיס `C`, וה-`break` מסיים את ה-switch.
> `switch` קופץ ל-`case` המתאים ורץ משם **עד שהוא פוגש `break`**, גם דרך ה-cases שאחריו. בגלל זה כל case מסתיים בדרך כלל ב-`break;`.

## באיזה מהמשתנים האלה **אי אפשר** להשתמש כערך ב-`switch (...)`?
- [ ] `char key`
  > `char` עובד מצוין, למשל `case 'A':`.
- [x] `float voltage`
  > נכון. `switch` עובד רק עם ערכים שלמים: `int` ו-`char`. בשביל `float` משתמשים בשרשרת `if` / `else if`.
- [ ] `int mode`
  > `int` הוא הטיפוס הנפוץ ביותר ל-switch.
- [ ] `int n`, הערך שמחזירה `sscanf`
  > הערך שמחזירה `sscanf` הוא `int` רגיל, אז אפשר לעשות עליו switch, למשל `case 2:`.
> `switch` משווה `int` או `char` אחד לערכים קבועים. הוא לא עובד עם `float` או עם מחרוזות, ולכן פקודות טקסט משווים עם `strcmp` בשרשרת `if`. וזכרו גם: הצהירו על כל המשתנים שאתם צריכים **מעל** ה-switch, אף פעם לא בתוך case.

## איזו שורה מכניסה את הערכים של `speed` ו-`temp` לתוך `msg` כטקסט `SPEED ... TEMP ...`?
```c
char msg[40];
int speed = 150;
double temp = 23.5;
```
- [ ] `sprintf("SPEED %d TEMP %lf", msg, speed, temp);`
  > המחרוזת שאליה כותבים באה **ראשונה**, לפני טקסט הפורמט.
- [x] `sprintf(msg, "SPEED %d TEMP %lf", speed, temp);`
  > נכון! קודם המחרוזת שאליה כותבים, אחר כך טקסט הפורמט, ואז הערכים באותו סדר כמו קודי ה-`%` שלהם: `%d` בשביל ה-`int`, `%lf` בשביל ה-`double`.
- [ ] `sprintf(msg, "SPEED %lf TEMP %d", speed, temp);`
  > הקודים הפוכים. `speed` הוא `int` וצריך `%d`, ו-`temp` הוא `double` וצריך `%lf`. כל קוד חייב להתאים לטיפוס של הערך שלו.
- [ ] `msg = sprintf("SPEED %d TEMP %lf", speed, temp);`
  > `sprintf` לא מחזירה את הטקסט עם `=`. נותנים לה את המחרוזת, והיא כותבת את הטקסט לתוכה.
> `sprintf(string, "format text", values...)` היא `printf` עם ארגומנט נוסף אחד בהתחלה: המחרוזת שאליה כותבים. הטקסט הקבוע מועתק כמו שהוא, וכל קוד `%` מוחלף בערך הבא.

## איזו שורה קוראת את המספרים מתוך `line` לתוך `speed` ו-`temp`?
```c
char line[] = "SPEED 150 TEMP 23.5";
int speed;
float temp;
```
- [ ] `sscanf(line, "%d %f", &speed, &temp);`
  > המחרוזת מתחילה במילה `SPEED`, שהיא לא מספר, אז `%d` נכשל מיד ושום דבר לא נקרא. גם הטקסט הקבוע חייב להופיע בפורמט.
- [ ] `sscanf(line, "SPEED %d TEMP %f", speed, temp);`
  > הפורמט נכון, אבל `speed` ו-`temp` הם משתנים פשוטים, אז הם צריכים `&` לפניהם.
- [ ] `sscanf("SPEED %d TEMP %f", line, &speed, &temp);`
  > המחרוזת שממנה קוראים באה **ראשונה**, ואחריה טקסט הפורמט.
- [x] `sscanf(line, "SPEED %d TEMP %f", &speed, &temp);`
  > נכון! הטקסט הקבוע `SPEED` ו-`TEMP` מתאים למילים ב-`line`, `%d` קורא 150 ו-`%f` קורא 23.5, וה-`&` מאפשר ל-`sscanf` לשמור אותם.
> `sscanf(string, "format text", &var1, &var2...)` היא `scanf` שקוראת ממחרוזת. כל טקסט קבוע בפורמט חייב להופיע במחרוזת בדיוק כמו שהוא כתוב, וכל משתנה פשוט צריך `&`.
